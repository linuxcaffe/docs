# Sync

nb-web syncs notebooks using git. Each nb notebook is a git repository in `~/.nb/<name>/`. Syncing means committing any uncommitted changes and pushing to (and pulling from) a remote — typically a private GitHub repository.

---

## The model

- **One git repo per notebook.** `~/.nb/home/` is its own repo, `~/.nb/work/` is another, etc.
- **One branch per notebook on the remote.** A notebook named `home` pushes to a branch called `home` on its remote, not `main` or `master`.
- **nb-web does not call `nb sync`.** It uses git directly. This is intentional — `nb sync` can auto-create notebooks from remote branches in ways that are hard to predict. nb-web's sync is explicit and scoped to one notebook at a time.

---

## Sync status indicators

The **logo button** in the top-left corner changes color:

- Normal — everything committed and pushed (or no remote)
- **Yellow tint** — uncommitted changes or unpushed commits in the current notebook

The **Sync button** in the menu header shows the active notebook name and its status:  
`Sync home · 3 unpushed` — three commits waiting to push.

The status updates immediately when you switch notebooks, save a note, or open the menu.

## Wiring a notebook to a remote

Before you can sync, a notebook needs a remote. Open **Menu → Notebooks**, click a notebook, and look at the sync section.

### Connect to an existing remote

Paste the SSH URL of an existing GitHub (or other git host) repository and click **Wire**. nb-web will:

1. Add `origin` pointing at your URL
2. Set the tracking config for the `master` branch
3. Push `HEAD:<notebook-name>` to create the remote branch

### Create a new GitHub repo (requires gh CLI)

If the repository doesn't exist yet, use **Create & Wire**:

1. Choose Private or Public
2. Click **Create & Wire**

nb-web calls `gh repo create <user>/<notebook> --private` (or `--public`), adds the remote, and pushes — all in one step. On failure the remote is rolled back so you can retry cleanly.

> Requires `gh` installed and authenticated (`gh auth login`). See [INSTALL](docs:12).

---

## Syncing

Once a notebook is wired, a **Sync** button appears in the notebook detail panel (Menu → Notebooks → select notebook). Click it to commit any pending changes and push/pull.

You can also trigger sync from the **Sync button in the menu header** — it targets whichever notebook is currently in focus.

After a sync, nb-web reloads the notebook detail so you can see the updated unpushed count.

## Hard rules

These are operational lessons, not suggestions:

**1. Set `NB_AUTO_SYNC=0` in your shell.**  
```bash
echo 'export NB_AUTO_SYNC=0' >> ~/.bashrc
```
nb's auto-sync can run in the background and create commits that conflict with nb-web's sync. Disable it.

**2. Do not run `nb sync` while nb-web is running.**  
Use nb-web's sync UI instead. Running both at once risks commit conflicts and unpredictable remote state.

**3. Do not run `nb browse --serve` alongside nb-web.**  
The nb browse daemon conflicts with nb-web's sync model. nb-web-launch kills it automatically on startup.

**4. Before any git recovery operation, run:**  
```bash
git -C ~/.nb/<notebook> clean -fd
```
Untracked files left by nb operations can interfere with reset and checkout. Clean first, then recover.

---

## Danger zone

The notebook detail panel has a **Danger Zone** section for destructive operations:

- **Delete local** — removes the notebook from `~/.nb/` on this machine only. The remote branch is untouched.
- **Delete remote branch** — removes the branch from GitHub. The local notebook is untouched.

Do them in sequence for a full wipeout: delete remote first, then local. This order means you can always see the remote state before it's gone.

> There is no undo. Deleted local notebooks are gone (unless you still have the remote). Deleted remote branches require a force-push to restore.

## If things go wrong

**Notebook shows hundreds of unexpected unpushed commits:**  
Stop. Do not push. This usually means the notebook has phantom commits from a corrupted sync. Check with:
```bash
git -C ~/.nb/<notebook> log --oneline origin/<notebook>..HEAD | head -20
```
If the commits are not yours, the notebook is contaminated. Your options are:
- Reset to the remote: `git -C ~/.nb/<notebook> reset --hard origin/<notebook>` (loses local changes)
- Delete local and re-clone from remote via Wire

**Wire fails with "repository not found":**  
The remote repo doesn't exist yet. Use **Create & Wire** instead of **Wire**.

**Wire fails with "push rejected":**  
The remote branch already has commits not in your local repo. Pull first:
```bash
git -C ~/.nb/<notebook> pull origin <notebook> --rebase
```
Then retry sync from nb-web.

**Logo stays yellow after syncing:**  
Check for uncommitted files:
```bash
git -C ~/.nb/<notebook> status
```
nb may have left untracked files. `git clean -fd` removes them, then sync again.
